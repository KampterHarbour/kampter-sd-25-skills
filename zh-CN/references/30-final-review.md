# 最终检查与交付

每次交付最终提示词或重写提示词前立刻读取本页。只有检查发现实质问题时才返回对应任务页。

## 按优先级解决问题

1. 超出官方范围或有无依据声明。
2. 指令冲突。
3. 缺少任务关键输入。
4. 时间轴、素材或连续性模糊。
5. 可读性和风格润色。

有硬范围违规或关键矛盾时，不要先润色。

## 通用检查

- 任务类型和请求一致。
- 时长、参考数量和媒体总时长符合 00-core-constraints.md。
- 有一句话说明主体、场景、可见变化和预期效果。
- 每个素材都有标识和具体职责；未见素材没有被虚构。
- 纯音频驱动需求写清音频职责，并确认或声明画面假设。
- 时间段连续、不重叠，并且总和等于需求时长。
- 每段都有可观察动作或变化。
- 镜头、动作、光线、风格和约束不冲突。
- 需要时明确跨镜头的身份、产品、空间、光线和声音锚点。
- 台词和声音提示符合其时间窗口。
- 负向约束简洁、具体且与正向目标兼容。
- 没有占位符或隐藏假设。
- 模式或能力名称与 00-core-constraints.md 一致，且未被改写成 API 或质量声明。
- 涉及官方支持的回答已按 90-source-notes.md 核对。
- 不出现承诺、API 声明或自动化说法。

## 任务专用检查

| 任务 | 验证内容 |
| --- | --- |
| 新生成 | 开场、推进和落点清晰；素材职责不互相碰撞；适用时使用时长专用官方写法。 |
| 编辑 | 目标、变化、生效时间、范围、不变元素和高级标注工具/方位明确。 |
| 延长 | 方向、结束状态、连续性策略、转场逻辑、新动作、最终状态和时长计算明确。 |
| 白模 | 粗/细职责、继承信息、重设计信息、对应关系和引导叠层处理明确。 |
| 诊断 | 原始意图、缺陷、最小修复和完整重写明确分开。 |

## 最终回复形状

只保留有用区块：

- 创意确认：一到两句。
- 可直接使用的提示词：一个干净代码块，内部不夹分析。
- 素材对应与假设：仅列真实映射和假设。
- 可选变体：最多一个，且必须有明显策略差异。

诊断任务遵循 24-prompt-diagnosis.md 的格式。
