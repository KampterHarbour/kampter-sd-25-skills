# 需求澄清与路由

先读取 00-core-constraints.md。仅当请求不完整、任务类型不明确或用户需要引导式协作时读取本页。除非请求确实包含多个任务，否则下一步只读取一个任务页。

## 必须产出

形成足以撰写提示词的紧凑创意需求卡，或指出阻止出稿的一到三个缺失决定。

## 识别任务

| 用户信号 | 任务 | 下一步读取 |
| --- | --- | --- |
| 新做一条视频，没有需要保留的原视频 | 新生成 | 20-generation.md |
| 仅由音频参考驱动的新视频 | 新生成 | 20-generation.md |
| 修改、替换或让已有视频中的对象变化 | 编辑 | 21-editing.md |
| 接着上一段、继续或追加已有视频 | 延长 | 22-extension.md |
| 白模、animatic、调度或三维布局 | 白模 | 23-white-model.md |
| 为什么不对、优化提示词或结果跑偏 | 诊断 | 24-prompt-diagnosis.md |

若涉及两个任务，先说明顺序。例如，先诊断原提示词，再撰写编辑指令。

## 匹配对话深度

| 用户状态 | 行为 |
| --- | --- |
| 只有一句模糊想法或不熟悉术语 | 每轮最多问三个高影响问题，提供两到三个具体选项并推荐一个。 |
| 给出分镜、时间码、素材职责或技术语言 | 保留已有结构，只问缺口或冲突。 |
| 给出已有提示词或成片偏差 | 重写前取得原提示词、期望结果和观察到的偏差。 |

不要向用户贴模式标签。

## 按影响力提问

只询问会实质改变提示词的未知项：

1. 任务类型，以及原视频是否必须保持。
2. 核心内容和希望观众感受到的效果。
3. 时长与交付方向。
4. 主体、场景和一个可见变化或故事转折。
5. 参考素材及每个素材的职责。
6. 视觉语言、镜头、节奏、声音、必须保留项和必须避免项。

用户要求直接出稿时，对低影响项做默认选择并列为假设。

## 创意需求卡

内部维护此卡，只在确认有帮助时展示：

~~~text
目标与受众：
任务与交付限制：
一句话创意：
主体 / 场景 / 可见变化：
参考素材对应：
视觉与镜头策略：
声音策略：
必须保留 / 必须避免：
假设：
~~~

在以下内容已知或明确假设时出稿：核心内容、预期效果、任务类型、时长或合理默认、主体、关键动作、场景、素材职责和无冲突限制。不要强行要求每个字段都做决定。
