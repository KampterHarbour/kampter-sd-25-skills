# Quality Checks

## Preflight checklist

输出“最终提示词”前逐项检查。只在发现问题时向用户展示检查过程。

### 1. Mode and hard limits

- 已明确是标准生成、超长模式、编辑、延长还是白模工作流。
- 标准生成、超长模式和延长时长符合 `capabilities-and-limits.md`。
- 图片、视频、音频数量未超出官方上限。
- 多个参考视频或音频的总时长未超限。
- 没有把即梦创作手册中的能力改写成 API 参数。

### 2. Intent

- 一句话能说清谁、在哪里、发生什么变化、希望得到什么效果。
- “内容”和“效果”都存在，不是只有形容词。
- 目标观众、用途或叙事落点与镜头策略一致。

### 3. Materials

- 每个实际使用的素材都有稳定标识和明确职责。
- 主体、动作、运镜、场景、风格与声音参考没有混写。
- 未看到素材时没有臆测内容。
- 多素材要求没有互相覆盖或争夺同一控制目标。

### 4. Timeline

- 所有时间段连续、不重叠，结束时间等于总时长。
- 每段都有可观察的画面变化，不只有情绪词或风格词。
- 动作有合理前因、过程和结果。
- 短时长内的场景、动作、转场和台词数量可以完成。
- 镜头运动与主体动作不会互相抵消或产生逻辑冲突。

### 5. Continuity

- 人物身份、脸、服装、道具和产品外观有明确稳定项。
- 空间方向、屏幕方向、光源、时间与天气变化合理。
- 编辑任务说明未编辑部分保持什么不变。
- 延长任务说明原片末态、连续锚点和新增变化。
- 白模任务说明继承与重设计的边界。

### 6. Sound

- 台词、旁白、音乐、环境声和关键音效各自职责清楚。
- 重要声音有触发时间，并与可见动作同步。
- 不需要声音时明确“无旁白”即可，不机械填满声音层。
- 台词长度适合对应时间段。

### 7. Constraints

- 负向约束具体、短而重要，不是几十个通用缺陷词。
- 正向要求与负向要求不冲突。
- 全局强化只强调跨镜头稳定项，不重复整段提示词。
- 没有“必然成功”“百分百一致”等不实保证。

## Common failure patterns and repairs

| 问题 | 典型症状 | 修复方式 |
| --- | --- | --- |
| 形容词堆叠 | “高级、电影感、震撼、梦幻”但不知道拍什么 | 补主体、动作、场景变化和摄影落点 |
| 分镜过载 | 10 秒塞入五个场景、三段台词和多个转场 | 保留一个主要变化，合并或删减镜头 |
| 素材职责模糊 | “参考图片1、视频1” | 分别指定外观、动作、运镜、场景或声音 |
| 镜头指令冲突 | 同段既固定机位又快速环绕 | 选择主策略，或拆到相邻时间段 |
| 主体漂移 | 人脸、服装、产品或道具跨镜头改变 | 在全局设定和强化中写稳定锚点 |
| 编辑范围扩大 | 只想改盒子却整段风格都变化 | 写目标、位置、有效时间和保持不变项 |
| 延长像重新开场 | 新段重复建立场景或人物突变 | 写原片末态、接续动作、镜头速度和声音桥 |
| 白模味残留 | 最终画面仍灰白、空背景、材质未完成 | 明确白模只负责哪些信息，并指定最终材质、灯光和环境 |
| 约束过长 | 大量“不要”削弱主要目标 | 只留 3-6 个最高风险约束，补强正向目标 |

## Delivery test

最终交付前问自己：

1. 一个没参加前面讨论的人，能否只看提示词就理解成片？
2. 每个素材、时间段和声音事件是否都有明确用途？
3. 用户能否直接粘贴使用，而无需删除解释或未替换占位符？
4. 所有推测是否已放在“假设”中，而不是藏在最终稿里？

任一答案为“否”，先修正再交付。
